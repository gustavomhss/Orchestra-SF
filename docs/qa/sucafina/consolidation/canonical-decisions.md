## Method

The script recomputes every decision from the matrix, the ledger and the git object database. The
ledger supplies the bundle of each path and the guard list; git supplies ancestry, blob contents and
head commit times. Exported names are extracted with `parseExportNames` (declarations, named export
lists, namespace re-exports and `default`), only for TypeScript/JavaScript blobs.

Rules are applied in the mandated order, and every path records the rule that decided it plus a
rejection reason for every source that lost:

1. **ancestry** — a source whose head is an ancestor of another source head cannot win. The decision
   only lands here when a single maximal head remains.
2. **base-superset** — a source whose export set is contained in the base blob's (non-empty) export
   set is superseded by base. When this rejects *every* source, base itself is canonical: the entry
   carries `chosen_pr: null` and the base blob as `chosen_blob`.
3. **export-superset** — a surviving source that is a strict export superset of every other survivor.
4. **newest-head** — the surviving source with the newest head commit time; each rejection records
   the compared export counts and both commit times.
5. **NEEDS_INPUT** — a tie on head time is never guessed, whether or not the export sets agree.

Guards, all of which abort the run instead of guessing:

- Every diverged path must exist in the ledger with the same bundle as the matrix.
- `FINAL` (immutable receipt) paths are refused outright; none of the 407 diverged paths is `FINAL`.
- Every matrix source PR must have a ledger record for that path.
- The ledger sha256 must match the matrix, so a stale ledger cannot silently change decisions.
- Each decision must account for every source exactly once (chosen plus rejected), and the number of
  entries must equal the number of diverged paths.
- The run exits non-zero when any path is `NEEDS_INPUT`.

Recompute and verify:

```
node script/sf-ci/canonical-decisions.mjs          # writes the JSON, exits non-zero on NEEDS_INPUT
node script/sf-ci/canonical-decisions.mjs --check  # fails when the committed JSON is stale
node --test script/sf-ci/canonical-decisions.test.mjs
```

The output is idempotent: `--check` reproduces the committed file byte-for-byte.

## NEEDS_INPUT

**None.** No path ties on head commit time, so rule 5 never fires and the script exits 0. The tie
branch is still implemented and covered by tests (`identical head time and identical export set`,
`identical head time with different export sets`), so a future matrix that introduces a tie will stop
the run and list the path rather than pick one.

## Notes for the owner

- **Strength of `base-superset`:** the rule compares export *surfaces*, not bodies. No source blob in
  this matrix is byte-identical to its base blob, so all 231 base-wins rest on "base already exports
  everything this source exports". In the sampled cases base is also the longer file
  (`apps/cli/src/sucafina-product/business-services.ts`: base 726 lines vs 708 in #29), which is
  consistent with base being the merged evolution, but the decision is surface-level evidence and is
  labelled as such in every entry.
- **One deletion source:** `modules/sucafina/Sucafinav1/product/interface/html.ts` has PR #327, which
  deletes the path (null blob). It is rejected under `base-superset` with an explicit
  "source deletes the path" reason, so the base file survives; the decision is recorded rather than
  inferred.
- **Bundle `NONE`:** 35 paths carry no bundle in both the matrix and the ledger. They are decided by
  the same rules and are kept out of every bundle port; they need a bundle assignment before replay.
- **Dependency direction:** decisions are recorded, not applied. Replaying a chosen blob still has to
  respect the runtime layering and the change-scoped CI cadence in `AGENTS.md`.
