# Procurement product ports

`createProcurementPort` reads the existing Procurement domain under the current actor. `list` returns the authorized request `queue`, open `stock`, and pending `aging` projections from the same selection; an unknown stage or an unproven entry time remains unavailable. `createProcurementCollectionRegistry` issues host-held collection and stage selectors. A selector selects records and never supplies authority.

`createProcurementSourceResolver` issues individual scoped selectors backed by the persisted source registry. Its `resolveForPreparation` is host-private. It reauthenticates the Request and returns the current evidence and scope for the selected principal, policy, access revision, period, and currency. A caller must restore the same period after a restart. Legacy global-version selectors are not accepted.

Use `createProcurementCollectionMemberIssuer` to convert a current collection member into individual evidence before persisting a work item. The host must still revalidate that individual evidence at admission and on later reads. `issueForActor` reissues an individual source for a different actor only after that actor's own authorization and a physical-incarnation check; unsupported subsets and collection references remain unavailable.

`createProcurementContractSource` reads explicitly selected Dashboard Vendor Contracts through the Dashboard source owner. The source reference is issued under that owner's current authorization. A contract's vendor text does not establish a supplier relationship. Amount currency is included only when the currency field was also selected and requested.

`createProcurementSourcingEvidence` is a host-private verifier input. It reads the authorized request, offers, submitted snapshot rates, and configured scoring criteria from the current domain and uses the existing comparison producer for eligibility and ranking. Offer revisions are revisions of the parent request scope; an offer has no independent revision. Missing FX and unrecorded policy are not replaced with zero or invented requirements.

`createProcurementDecisionPreparation` assembles read-only C02 material for a dossier. It checks that the request and comparison still refer to the same source; it does not approve or apply a command. `createProcurementScenarioPreparation` prepares only an explicit PR amount replacement present in a host-authorized recorded choice with matching evidence, currency, and period. Other operation shapes are rejected rather than being mapped by name.

`prepareProcurementMutation` currently accepts `Requests/save` for the existing requisition's title, justification, and estimated amount. It runs the actual domain on a copy, checks the actor and persisted scope, and rejects unrelated changes. WP11 owns the human confirmation, the C08 atomic transaction, and the receipt. For restart-safe reconstruction inside that transaction, recover the scope with `procurementPreparedScope` and use the retained evidence, command, operation ID, idempotency key, and target observation time. `staleProcurementPreparedMutation` produces only a conflict when the currently authorized snapshot proves a changed scoped version or command revision; missing or revoked authority is not converted to conflict. `procurementPreparedRevision` returns the actual command CAS revision, not the source evidence revision. Domain audit records use the actual apply time.

These ports do not themselves mount UI routes, issue human confirmation, or provide a finished C07 dossier. Their host consumers and the repository's scoped CI gate must be verified on the integrated candidate.
