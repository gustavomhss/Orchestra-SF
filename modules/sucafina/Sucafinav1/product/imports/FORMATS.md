# Import and export formats

This catalog describes the existing workbook and backup producers. A parsed file is data, not authorization; the selected target, actor, revision and human confirmation are checked separately. Workbook limits, invalid ZIP/XLS structures and duplicate headers fail before any partial result is eligible for application. Formula results, including zero, use the cached result; empty cells are not assigned a physical origin.

| Family and executor | Accepted inputs | Ignored or protected inputs | Rejections and export |
| --- | --- | --- | --- |
| Planner XLSX and legacy XLS: `import-workbook` | `Info` supplies Version ID metadata. OPEX and CAPEX accept their line IDs, descriptive fields, references, currency, measure and Jan–Dec amounts. Headcount accepts position identity, Include, Name, Title, Domain, Location, Type, Rate card, FTE, Start month, End month and Rate override. FX rates accepts Currency and USD per 1 unit; Rate cards accepts Rate ID, Rate card, Locations, Currency and Annual cost per FTE. | Calculated Total and FY cost are not inputs. Synthetic HR budget comes from headcount. Unavailable role/lock-protected sections remain unchanged with domain warnings. Unknown references follow the domain's existing warning rules. Unrecognized worksheets are omitted by the parser; a workbook containing no recognized worksheet is rejected. | Duplicate canonical sheets or headers, malformed values, conflicting revisions and unauthorized changes fail before Apply. Direct domain commands containing unsupported sheet keys are rejected. `exportPlanner` writes Info, OPEX, CAPEX, Headcount, Rate cards and FX rates. Salary-protected individual amounts, overrides and rate-card rows are omitted for unauthorized roles. |
| Planner roster: `import-workbook` | `All Members` maps Name, Title, Type, Leader, Location, Start Date/Start, End Date/End and Status into roster entries. | `Summary by Leader`, Tenure, Classification, Outlook and Notes are not roster or finance inputs. A locked version does not sync roster positions. | An auxiliary summary without All Members, All Members alongside Headcount, missing names and invalid dates are rejected. `exportMembers` is admin-only and emits All Members plus Summary by Leader; the exported talent columns are not Planner roster inputs. |
| Dashboard members: Talent Review `import` | All Members uses Name, Title, Type, Leader, Location, Start/Start Date, End/End Date, Status, Classification, Outlook and Notes under the Dashboard's admin authorization. | Summary by Leader is not passed to the command. Tenure is calculated. | Missing names, unknown leaders and stale member versions fail; replacement requires confirmation and versions. `exportMembers` emits the member and leader-summary sheets. |
| Dashboard projects: All Projects `import` | Projects Import or All Projects maps Name/Project Name, Description, Status, Risk, Priority, Project Manager, Start Date, End Date, Budget (USD), Spent (USD), % Complete, Notes and a recognized IT Leader. | Other workbook columns and unselected sheets are not passed as project values. | Invalid rows and revisions follow the original project import; replace requires confirmation. Existing project export remains the source format. |
| Dashboard operations: IT Operations `import-month` | Ticket Register supplies a selected full month's numeric Incident and Service Request Initial Balance, Open and Closed values, grouped by category. | SLA, Availability and Heat Map tabs are not ticket inputs; other months do not enter the selected-month command. | A missing month header, reserved category separator, missing numeric data, stale versions or invalid selected month is rejected. | Dashboard JSON backup: `backup-import` | The shared backup producer migrates the admitted JSON and applies the existing dataset revision and admin checks. | Current installation configuration and private product state are preserved; existing contract attachments are retained by identity. | Imported private product state, new file references and removal of a contract with an attachment are rejected. Export uses the existing public JSON backup and excludes private product state. |

The selected source scope may be narrower than a whole backup. In that case a replacement affecting fields or periods outside that scope is refused; a preview must not imply broader authority.

## Format, route, role and outcome matrix

The import workbench is reached at `/sucafina/planner?sf=imports` or `/sucafina/dashboard?sf=imports`. Its requests use the same authenticated surface and the `import-targets`, `import-admit`, `import-preview`, `import-detail` and `import-apply` modes. Admission binds the selected source, options and bytes; changing an option requires a new admission. Preview and detail return the public manifest, never the stored executable command. Only the human Apply route can commit.

## C02 impact and C04/C08 composition

Planner impact is produced by `projectPlannerSource` and `buildPlannerFinancialProjection` from the Planner owner. WP06 does not recalculate HR, FX, FTE or outlook. The manifest contains candidate components once and paired `before:`/`after:` values from the producer. Components and converted amounts retain USD; original-currency values retain their currency, FTE retains `unit=fte`, and FX retains its `USD/<currency>` unit. Missing data stays null/absent. Candidate nonmissing values are hypothetical until the human decision; an Apply receipt does not rewrite historical preview evidence.

Dashboard workbook preview/apply uses WP02's real `previewDashboardImport` and `applyDashboardImport`. The recovered seed `95faa3e66a5640ca37407b072c65eaf731d0ca1f` exposes five/seven arguments and no backup format. WP02 producer `4c36e6fc6e69e4dd1e98b5d0d5c2e50962ccfe80` was inspected and adds the optional `DashboardBackupAdapter` seam. The WP06-owned compatibility routing works with both signatures: workbook calls use the existing producer, while JSON backup uses the WP06-owned adapter over `executeDashboardBackupImport`. No WP02 file or backup business rule is copied or changed.

The CLI composition supplies the scoped Planner/Dashboard source resolver and the independent roster issuer. C08 must provide an actual transaction containing both the domain mutation and private preview/receipt updates; a storage fallback cannot satisfy atomic Apply. `import-detail` reads the current-authorized public manifest, detail, digest and receipt summary. `import-reference?importPreviewRef=...` reopens the same public view for the optional analysis consumer after current access, source and file checks; it never applies. The workbench accepts `?sf=imports&importPreviewRef=...` to display that simulation and leaves Apply as an explicit human action.

To reproduce the acceptance journey in a composed runtime, select a scoped target in the workbench, admit the original workbook, inspect cell provenance and before/after impact, cancel once and verify no domain mutation, admit again, Apply deliberately, inspect the durable changed/unchanged/rejected summary, reload and retry the exact manifest. Repeat with a target revision change, roster-only change, access revocation and changed admitted bytes. Export/download privacy must be checked on bytes, not only on visible cells.
