# Portfolio integration

`createPortfolioPort` evaluates a bounded set of nonempty candidate combinations. `createPortfolioPlannerHost` delegates each scenario and sensitivity request to the supplied `PlannerPort`; it does not implement a financial engine. `createDecisionCandidateResolver` resolves versioned alternatives through the authorized decision-case port. The host must resolve candidates under current authority, supply the canonical base and assumptions, assess every declared constraint from the domain result, and return the current C10 coverage references. It must revalidate each result's sources, coverage and access at egress. Unsupported operations and unavailable sources remain explicit failures.

`createPortfolioContribution` composes the decision-case resolver, Planner adapter, shared port, decision handoff and capability descriptors. The host explicitly enables only implemented operations; an empty list advertises none. `createPortfolioCapabilities` exposes the same port to the SF dispatcher. The composition root must supply its receipt factory and current authority, and register only the operations it can actually serve. The UI must call the same port. The host must persist the complete request and result together and retain `portfolioEvaluationDigest(request, result)`. The `preparePortfolioChoice` handoff requires that same digest and a current persisted human choice whose operations match the re-evaluated combination; it calls WP11's `prepareChanges` and never executes the resulting commands. WP11 owns application, receipts and partial recovery.

`createSensitivityEvaluator` accepts domain-backed sample and exact-threshold callbacks. A numeric threshold requires domain evidence, and an unavailable exact calculation returns only sampled points. The sensitivity host must revalidate every sample and threshold evidence before return; an unresolved category conditions the result. `createSensitivityV6Evaluator` attaches current coverage references, unit, engine version and threshold evidence; it rejects a mismatch with the legacy threshold. The resulting sample references must resolve through the host to their coverage and precision details.

Planner simulation is available through its domain adapter. Sensitivity is available only after its real Planner preview, authorized unit metadata and C08 storage are composed. Results are finite exploration, not proof of a global optimum. Pending or unquantified coverage cannot be reported as complete eligibility.

`createStoredPortfolioReader` reads only an existing ready native contribution associated with its persisted run and current authorized case. The host must revalidate the portfolio's stored analysis references. `createStoredPortfolioProjection` pairs that output with a real authorized domain projection and requires the host to revalidate their relationship; it does not create a new result reference. Legacy combinations without analysis are marked unavailable in the projection. For deterministic results, `createPersistentPortfolioPort` evaluates through the real portfolio port, checks existing scenario/comparison references through `createSfDecisionResultStore`, and persists the portfolio via that same C08 store. Its `read` can be passed directly to `createStoredPortfolioProjection`; UI uses `evaluateAndStore`, and `createPersistentPortfolioCapabilities` returns the same persisted output reference to the dispatcher. The host supplies the authenticated case and idempotency identity. The contribution does not advertise portfolio evaluation unless persistence is composed.

`createProductionPortfolio` composes the case resolver, Planner and C08 result store with the current business-evidence service. It combines only alternatives sharing a base and consistent assumptions, and checks every source under the caller's authority. The Planner's preview currently requires a fresh cost-coverage assessment: until a matching authorized assessment is available the factory exposes no interaction coverage reference; candidate coverage references remain available when the host resolves them. If no stored comparison exists, analysis is unavailable and criteria remain unknown. It never fills a missing assessment or infers a threshold. Sensitivity is advertised only when a real evaluator is supplied.

`createPlannerSensitivity` accepts the real Planner preview comparison, a case-scoped binding and revalidation for versioned parameter and result units. It stores each actual preview through C08 and rechecks its source, baseline, metadata and sample before returning. Raw previews keep their original conditioned status, null total and `preview-not-applied` restriction. Incomplete coverage permits only a sampled interval or an unavailable threshold; a proof about the known subtotal alone cannot establish an exact decision threshold. `createPersistentSensitivityPort` stores the final result and requires a durable WP11 criterion binding, reloads its original request and revalidates the current rule binding, case and referenced samples before returning the stored result. If C08 committed but binding failed, an exact retry reuses the original result and repairs the missing binding under current authority. A lost binding reply does not allocate another result. Stale or denied bindings remain failures. The canonical capability returns the stored reference, and requires the same receipt and authority checks as portfolio evaluation.

`createPortfolioCoveragePreview` composes the published Planner structural interval and WP11 C10 certificate. Its host must resolve authenticated current case, selection, rule, baseline, classification and evidence records, and provide a live authority/source fence. Included categories may share a component; the canonical domain continues to calculate that component once. Not-applicable entries require supported scope evidence. An omitted category is unresolved, and an explicit zero remains a quantified value. An interval qualifies samples only when all required categories and both scenarios have complete coverage, the canonical parameter and fixed components match, and every sample replays under current authority. The qualification is separate from the producer result and is revalidated at egress. Private interval identifiers are not exposed as durable C08 references.

With a qualified interval and the canonical exact-threshold callback, the sensitivity analysis can report an exact numeric boundary with `comparisonStatus: complete`. Its `hypothesis` disclosures retain the fact that the sampled changes have not been applied; it does not create a human choice, prepared change or receipt. Without both proofs the analysis stays conditioned. `createPortfolioProduct` accepts `resolveCoverageAuthority` and `exactThreshold` for this composition, and `createPortfolioProofVerifier` receives the equivalent `coveragePreview` and threshold callback for read-only reproduction. The verifier reconstructs the same certificate after service recreation and rejects changed rules, sources or authority. No UI or native consumer may infer application from mathematical completeness.

The published Planner also supports source observations with no operations or assumptions. Portfolio candidates may consume a real `source-scenario:` result without fabricating a write. Sensitivity uses only the `parameterOperation` issued by Planner for an existing confirmed source value; it preserves the stored empty request and varies that operation only in the hypothetical samples.

`createProductionPortfolio` can receive an authorized candidate coverage selector and analysis service. It verifies each candidate assessment against its current C10 reference, retains their references alongside the comparison references, and reads the compared scenario from C08 with the exact combined request digest. Criterion states must agree with the persisted comparison; without the service the criteria remain unknown. `promoteAlternative` is a human action that rechecks the selected combination and delegates creation and reassessment to WP11. Recording a choice and preparing domain changes remain separate authorized actions.

An analysis service may return `portfolio-analysis-not-yet-persisted` when no case alternative exists for the exact combination. The factory then exposes the conditioned preview so a person can promote it; access failures and stale results are never downgraded to that state.

`catalog({ caseRefs }, context)` reads authorized cases and returns versioned candidate references, declared operations, assumptions, criteria and coverage. It does not invent parameter bounds. `preview(request, context)` returns an evaluation and its review digest without persisting a result; this supports the explicit human promotion step before a comparison is selected. Production persistence requires the WP11 portfolio binding, and sensitivity persistence additionally requires its criterion binding. Missing or stale bindings fail closed.

`createPortfolioProduct` composes those services for the host with explicit authority, current case selection, Planner, rule and result bindings. Its HTTP adapter checks the caller’s case and exposes discovery, preview, persisted evaluation, sensitivity, promotion and preparation. The host owns admission and supplies the proof services; this factory does not create grants or business rules.

`createPortfolioCampaign` stores a human-edited selection with a versioned case, explicit scope, exploration limit, criteria and authorized contract or project sources. Candidate effects are checked by the supplied domain producer, and AI contributions remain provisional until a separate human action. Source fences and read-only state version checks guard the write. Its historical reads are separate from current reads and reauthorize the original references; they do not promote or execute them. The host must compose the record issuers, proposal readers, operation verifier and protected state writer before exposing these methods.

`createPortfolioCandidateHistoryReader` supplies the optional historical-candidate port used by campaign and portfolio provenance readers. After a legitimate alternative revision replaces v1 with v2, it resolves v1 from a case transaction snapshot or a choice linked to its exact ledger event, then requires the original C08 scenario request/result and current authorized ancestry. The expected candidate digest must come from the authenticated campaign or portfolio binding. Current case authorization and all original evidence are checked twice; a digest alone, a later alternative with the same ID, a replacement incarnation or an inaccessible source is insufficient. This reader is read-only and never recreates a decision or ledger entry.
