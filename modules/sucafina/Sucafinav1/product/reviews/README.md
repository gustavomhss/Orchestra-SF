# Review integration

`createReviewPort` requires the existing protected product state and the authenticated host request for each call. `select` resolves the ordered section references against the current principal and returns domain projections and the producer’s selected record count, without recalculating values or treating metric count as record count. It must redact restricted titles, records and counts and return a non-identifying refusal when access is unavailable. `authorizeSections` rechecks the current right to each section, including empty sections whose titles or counts may be restricted. `authorizeComments` rechecks current C06 access to every captured comment. `authorizeSensitivity` rechecks the scenario, result and coverage references in any captured sensitivity. `revalidate` checks every `SourceRef`, including comment sources. `revalidateEvidence` resolves every `BusinessEvidenceRef` against current authority; historical access must be explicitly established by the source resolver. Do not implement these authorization callbacks as unconditional allows. A selection must use the same installation, project, principal, policy and access revision as its binding.

`preserve` uses the host clock plus a target incarnation, storage revision and idempotency key supplied by the authenticated host. An exact retry reads the durable receipt before consulting mutable source projections. A successful response contains the captured projection and C06 comment versions; the current conversation remains owned by collaboration. `read` rechecks source and evidence access and returns the whole review only when all captured sources remain authorized. This conservative refusal prevents counts and titles from exposing restricted content.

`createMeetingView` reads the review at each navigation and comparison, rechecks both versions before rendering a comparison, and asks the host to create a new review when an update is chosen. Mount `element` in the product shell, call `refresh` when the host detects an access or source change, and dispose the view when leaving. The host must remove the mounted view immediately when it revokes its binding. `requestUpdate` must perform a fresh authorized selection and preserve a new identity; it must not mutate the previous review.

`createReviewCapabilities` provides C16 descriptors, using the host's `SfDomainValidation`. The host must implement `artifacts.put/read` with durable private storage. It must bind bytes to the returned artifact reference, selected section refs and the preserved review, revalidate authorization at every byte download, and never expose files by an unauthenticated path. `readArtifact` returns metadata; it is not a byte-download endpoint. Register these descriptors only when the selection, evidence resolver and artifact store are composed with real producers.

When a selected view includes a chart, the host may supply the `resolveBiPresentation` result as `ReviewSection.chart`; its series values are verified against the captured projection. For a timeline, attach the real `resolveTimeline` result as `chart.timeline`; for a waterfall, attach the real `resolveWaterfall` result plus its final value ID as `chart.waterfall`. For BI11, attach the authorized sensitivity result and explicit axis units as `chart.sensitivity`. Compatible single-unit BI01 financial trajectories and BI03/BI05/BI06/BI07 bars, BI04 separate capacity/cost panels, BI08/BI10 timelines, BI02/BI09 waterfalls and BI11 evaluated sensitivity points are rendered from captured series in both formats; category bars paginate without dropping entries. Captions state series, scale, period and values. Other or incompatible chart kinds are declared unavailable in the export. The renderer consumes only the captured projection, selected sections and preserved comments. Its document output is not yet the complete product acceptance: WP05 chart presentations and WP14 expected/observed projections require their real producer handoffs, and long output requires rendered-page inspection. CI and integration evidence are tracked separately from this interface.
