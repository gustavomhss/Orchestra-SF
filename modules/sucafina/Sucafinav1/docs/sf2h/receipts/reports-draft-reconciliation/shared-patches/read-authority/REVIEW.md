## Behavioral contract

- A state read that fails, is interrupted, or returns incomplete/malformed content remains unavailable. A current authorized state read with an absent selected thread proves that target is gone and returns denied. No target bytes accompany either error.
- The Request object and authenticated principal/access/policy binding remain pinned. Real denial, changed binding, removed/replaced target, changed thread scope or lost participant/source authorization returns denied/HTTP403.
- A reply/edit that changes the thread between the two authorized reads returns stale/thread-content-changed/HTTP409. It does not return a partial thread or claim current authority for a write.
- Threads preserve immutable source scope and the identities, author and source basis of existing messages. Replies and edits may change the content/version, but cannot retarget an existing discussion. This comparison is reused by recipient and historical readers.
- The recipient adapter cannot fall through after denied, stale or typed read uncertainty. Existing fallback for unsupported source projections remains independently authorized by the base reader.
- Strict read authority distinguishes BusinessEvidenceResolution states. Explicit revoked/replaced/missing/invalid or ref/binding mismatch denies; provider exception, unavailable, stale or incomplete output cannot become boolean denial. The public base/recipient/history read boundaries normalize uncertainty into an unavailable PortResult before HTTP, including for direct callers. After an exception, a fresh false authority revalidation takes precedence as denied; inconclusive revalidation remains unavailable. Unknown never grants access.
- Legacy source probes remain intact for independent actor-scoped reissue. The optional historical probe of a nonreview thread may be unavailable while a new current reference is still independently issued and authorized. A Reports C05 pin requires its historical authority and remains unavailable when that proof is uncertain.
- C05 review-context readers retain upstream unavailable results. Boolean authorize returns false for explicit denial/invalid input and throws for read uncertainty. The HTTP review-context route distinguishes that uncertainty from false.
- C05 services expose a strict read-only evidence check while retaining existing preview/preserve probes. The read checks evidence before legacy boolean selection gates and again before returning content. Provider unavailable/stale/exception remains unavailable; explicit revoked/replaced/missing/invalid remains denied. The producer normalizes exceptions into a PortResult and revalidates the captured Request. A successful authorized storage read with a missing or different C05 target now returns denied/review-target-changed directly, without inferring denial from a legacy unavailable reason.
- State read errors during the review precondition of question/reply/edit are preserved; they no longer fabricate denial. Mutation code still uses the same human intent, C08 expected version, idempotency key, source fences and recipient commit checks.
- The HTTP adapter preserves explicit producer statuses. Admission exceptions return503. Review-read/closure no longer emit403 merely because the producer returned a non-ok result. Original binding fence/echo and browser access probe from36 remain in the cumulative unit.
- Review-thread-context/read/closure admissions preserve their typed status and convert exceptions to503. Post-admission read exceptions revalidate authority: confirmed false returns403 and uncertain failures remain503. The shared focus probe treats an absent response binding header as inconclusive; an explicitly different header or authenticated401/403/login response still clears private state.
- The installed protectSfReviewReads wrapper now has typed snapshot and receipt proofs. It preserves producer and C08 failures, including the second canonical read and the after-read snapshot. Proven C05 body/receipt/binding/principal changes still deny. A changed complete snapshot with the exact same C05, receipt and authority remains recoverable; after the existing two read attempts it returns stale/review-read-changed. It does not cache failures or treat a missing precomputed proof inside a C08 group as revocation. Successful C08 proofs still have no await after their final fence.
- The installed review-history captures path propagates storage uncertainty rather than converting it to an absent capture. Two independently authorized scoped source reads with different content raise recoverable uncertainty. Actual binding refusal, removed target/receipt or refused scope still returns the existing negative result. The review-calculation-history change only narrows the authority parameter type to the fields actually consumed; no runtime calculation logic changes.
