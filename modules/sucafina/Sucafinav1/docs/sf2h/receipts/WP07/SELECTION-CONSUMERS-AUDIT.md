## Implemented corrections

- Agenda creation captures caller input and authority scope before asynchronous reads. It stores the displayed section bodies and one digest per section. Selection revalidates the real producers and refuses `stale/agenda-preview-changed` when data, record identities, versions, count, note, chart or C06 capture differs. Reordering and removing sections preserves their original bodies. Only the observation timestamp on C01 source references is excluded from the equality check: a fresh authorization read may advance that timestamp without changing the source. The displayed timestamp remains the captured one.
- An expired or released selection is refused after an in-flight producer read. Changes to the caller's arrays or binding object cannot change the cached selection.
- All Dashboard topic IDs, including Executive Dashboard and IT Performance Contract, are routed to the authenticated producer. WP07 does not invent singleton identity or override the producer's explicit refusal. Procurement accepts exactly the selected record instead of silently ignoring extra references. Forecast-side matching uses exact identity, avoiding prefix collisions.
- `ReviewHost.authorizeComments` now carries the complete preserved C06 message required by the real comment verifier. C06 reads keep historical comments accessible when later replies exceed the limit for a *new capture*. Capture still refuses the oversized conversation explicitly and never truncates it. Thread and historical-body snapshots are copied before asynchronous authorization checks.
- Review preview validates the returned section shape and matching period before dereferencing it. Persistence snapshots the input command and validates its identity, selection and concurrency fields. Recovery rejects a section whose period differs from its captured projection.
- `createReviewComposition` connects the source-owned agenda selector, Planner/Procurement ports, C06 current and historical readers, source mapping, current authorizations, review persistence and report storage. All authority callbacks are required; no unconditional allow or substitute store is created.
- `createReviewContributionConsumer` opens persisted C11 `DecisionBrief` and `MeetingMaterialProposal` through `createSfContributionReader`, checks case/version/digest, and rechecks referenced results or artifacts before returning a body. Decision results use the existing `createSfDecisionResultStore.read` when supplied. Material must match the actual preserved review, section order, counts and artifact metadata. Links contain authorized internal references only. The consumer creates no native execution or consumption receipt.

## Authored checks

`test/product/wp07/selection.test.ts` covers order/removal, independent periods, empty selections, producer refusal, denied Talent Review, caller mutation, expiry/release during a read, and the preview-to-preserve content race. The recovered all-topics test was corrected to grant Talent access for its positive case and revoke it before the negative case. An unselected section is correctly expected to return `needs-input`.

`test/product/wp07/thread-access.test.ts` covers exact preserved messages, changed message versions, current denial, oversized later conversations and snapshot isolation at the mapping callback.

`test/product/wp07/composition.test.ts` uses the real Planner producer, a consumed UI lease, and the protected state implementation over the repository's test persistence. It carries the real calculated projection through the composed agenda and review store, recovers it after recreating the composition, and rejects access after revocation. Missing Dashboard and C06 history producers remain explicitly unavailable in this test. This is not native execution, durable installation storage, three-product acceptance or visual export proof.

`test/product/wp07/contribution.test.ts` exercises the production C11 reader and run store on absent output and revoked access. It confirms that missing native output opens neither a review nor an artifact and yields no payload. It does not manufacture a successful `SessionV2` run or `SkillLoadReceipt`.
