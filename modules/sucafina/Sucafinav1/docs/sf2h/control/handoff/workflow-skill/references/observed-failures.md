# Observed failure patterns

These establish specific operational corrections, not a measured end-to-end speedup or completed product.

| Failure | Correction and evidence limit |
| --- | --- |
| Completed integrator received messages without waking; stack lag was about 40 minutes. | Resume the existing agent via followup_task. New commits were published; publication is not acceptance. |
| Helpers lacked producer APIs at their supplied base. | Verify input blobs and reconcile the existing workspace. Never reset dirty work or move another active writer. |
| Supervisor assigned tiny patches and centralized decisions. | Assign complete existing tasks and delegate WP consolidation to its lead. Throughput gains still require completed PRs. |
| Auxiliary branches and incompatible transports isolated helpers. | Verify primary-tree access and direct communication. Ordinary native Luna-to-Terra handshakes produced integrated production code. |
| Grok patches invented scopes or weakened failure checks. | Review actual patches against criteria and reject unsafe portions. Diversity does not establish correctness or independent review. |
| Ready producers waited behind another wave. | Reconcile status and resume the same IDs, preserving interruption/cancellation controls. |
| A small advisory follow-up carried a large history. | Bound packets and resume with deltas. One observed request used 23,261 input and 947 output tokens; this is not a campaign-wide cost breakdown. |
| An unconfigured headless write probe was treated as proof that Grok could only return patches; forced plan/read-only flags kept implementation on Terra. | Later direct writes succeeded using documented scoped allow rules. Verify actual client permissions before imposing model roles or a patch-materialization bottleneck. |

For a behavioral review, consider a completed integrator, dirty shared WP tree, missing producer API and read-only helper. The operator should resume the existing instance, preserve dirty work, assign the actual producer, retain complete task criteria and never invent permissions or CI proof. Review this scenario without executing product tests or mutating a live campaign.
