## Failure budget — fast red, complete green

The full Sucafina Bun suite and the SF browser unit directory use
`--bail=5`, while the three installed Playwright journeys use
`--max-failures=2`. **This stops only after a real failure.** A successful
qualification still runs every selected test; a failed/incomplete selection
never produces a passing receipt or `sf/verify`. This prevents ten
consecutive 165-second failures from consuming a CI runner merely to repeat
an already decisive red verdict. For diagnosis, run the named failing test
with the Linux-only surgical runner. No timeout, permission or expectation
has been relaxed.

The Linux-only request selector regression runs in the independent preflight
before product typechecks, and repository guards run even if product typechecks fail, so the quality
of this CI migration can be reviewed separately from SF product failures.

## Required SF CI

`.github/workflows/sf-ci.yml` intentionally has no path filter and no
Windows/macOS matrix. An Ubuntu runner prepares native Omni once; the five
normative Bun suites and three actual SF Playwright journeys execute as a
bounded, explicit matrix. The only required final result is `sf/verify`,
which rejects a missing/skipped/cancelled job, missing/extra suite, empty
results, report/receipt digest mismatch, wrong commit/run/attempt, non-Linux
runner and failed or skipped tests.

`sf/static-and-contracts` retains Linux host/product typechecks, generated
client and Atlas boundary, E2E typecheck, actual Web build, spawn boundaries
and guardrails. We do not report this pilot as green without a run.

The initial pilot executes **all eight approved CI families**, not
a new untested dependency-based filter. Only pull-request or manual
dispatch triggers the pipeline; push no longer schedules a redundant
copy that gets cancelled. Browser unit tests run the full
`packages/app-shell/test-browser/sucafina-native` directory, including
new files automatically, rather than the unrelated canonical browser
tests. The independent Linux-only `test-ci` selector regression runs
on the static lane. The CLI and Atlas-Business families
now read their explicit test-file arguments exclusively from
`sf/ci/suites.json` instead of upstream compiled distribution and redundant
generator tests. CLI includes host installation, admission, Task/Relay
wiring, listener policy and Linux service boundaries. Atlas includes
business-memory ports, catalog, surface and scanner-clock; generated bytes
still run through the static contract gate. This is a scoped replacement
of the *full upstream* CI-CLI and CI-ATLAS-BUSINESS recipes: independent
review must approve coverage equivalence before required checks migrate.
Multi-platform compiled CLI build acceptance is not a dependency of the
VM-hosted SF unit gate; Linux native release acceptance remains blocked
until actual application packaging and deployment are available.

The aggregator checks all upstream job conclusions **before** attempting any
artifact download. A failed unit, UI, static or Omni job produces a precise
RED precheck listing each failed/cancelled/skipped/missing job; no misleading
artifact-download error precedes that diagnostic. Only successful upstream
runs download the eight receipt directories. The aggregator keeps each
artifact in a distinct named directory and refuses missing, extra,
duplicate or misbound receipts. This removes the 59-job
canonical-multi-OS topology. Later PR-only path reduction requires a
separately proven classifier with unknown/shared/lock/config changes falling
back to full coverage. No hidden missing-test shortcuts.

The source checkout and receipts point to the *actual* tested `github.sha`.
For a pull request that is normally the merge commit, not its head. A green
pull-request merge cannot replace a final qualification of frozen product
candidate `C`. Any product/config/test mutation creates a new candidate.

Receipts are machine-checked. Only successful suites upload evidence.
Before upload, the Playwright JSON is reduced to file identity, per-test
execution statuses and aggregate counts: no attachments, traces, cookies,
raw stdout/stderr or operator data are retained in the artifact.
Raw failure details remain in the restricted Actions job log.
Do not upload Playwright traces, cookies or real business data. Each Playwright spec runs
one worker with zero retries. Failure means RED; a deadline does not turn
a proof into NOT_APPLICABLE.

## Release boundary

`.github/workflows/sf-release.yml` is deliberately an **inert red gate**.
The separate `azure-hardening` branch currently contains an Azure foundation
with Caddy replying 503, not a running SF application. No release can pass
until the real, protected, owner-approved Azure activation is wired to
this exact artifact and SHA, plus Entra/origin/authorization, persistence,
rollback/restore and AM01–AM06 evidence. A 200/health endpoint or an empty
staging parameter is never acceptable.

## Adoption checklist

1. Push **only** the isolated CI branch and observe its jobs and self-tests.
2. Fix runner/selector problems in the CI branch; classify real product
   failures separately rather than altering runtime policy.
3. Confirm all eight receipts, invalidation/negative controls and Linux-only
   execution. Keep failed/blocked proofs visible until resolved.
4. Qualify exact frozen C, complete AM01–AM06 and independent reviews.
5. Only then propose a separately approved branch-protection migration,
   retire the old Epic and integrate/qualify Azure application activation.
